# YukiPan

## 总述

YukiPan 是一个私人的云端存储应用, 域名定为 `pan.yeastar.xin`

YukiPan 的诞生是因为: OpenList 功能太臃肿了, 并且形态单一, 不满足我的多种要求, 并且使用过程中出现了非常多的 Bug

YukiPan 的设计纲要是这样: 云端存储分为三部分: 私有存储, 图床, 访客空间

* 私有存储: 相当于一个文件资源管理器, 用来给我自己管理文件用 (读写需要鉴权)
* 图床: 一个公开可访问的页面, 主页模仿 `https://photos.google.com/` 的样式按相册展示图片, 并且也支持我上传图片, 创建相册等等
* 访客空间: 一个所有访客都可以访问的页面, 支持上传/下载

需要注意的事项是, 做好鉴权防护, 所有公开页面做好网络风暴防御

## 1. 技术栈

### 后端

强烈建议使用 Rust。相对 Python, 依赖和运行时更好管, 类型与错误处理让容错更高, 内存占用也更容易压住。这台机器内存不宽裕, 网盘又要过文件流, 后端必须能把内存钉死在可控范围里。

框架、监听地址等具体绑法放到第 8 章一起写。

### 前端

还没定档, 需要评估后再选。

图床主页要模仿 `https://photos.google.com/` 的相册展示, 还有文件管理器、上传进度这些交互。对一个成熟的 Web 项目来说, 可以走 Vue, 用 Vite 编译。评估时就看这件事: 这套交互用 Vue 是否更省事, 以及编译产物和运行时开销能不能接受。没评完之前不要先写死成某一种前端。

### 数据库

主存储用 PostgreSQL。限流和公开页的网络风暴防御用 Redis。

Postgres 管用户、会话、文件元数据、相册、标签这些要查询的东西。Redis 管短时计数 (登录失败、访客上传、公开页请求), 防风暴不走主库。

## 2. 私有存储

这一页就是一个文件资源管理器, 给自己管文件用。没登录进不来, 进来之后才是完整的管理 (浏览、上传、下载、改名、移动、删除)。私有区本身不长公开链接, 外人不能靠猜 URL 进来。

### 能做什么

按资源管理器来: 进目录、上传 (要有进度)、下载、预览、新建目录、重命名、移动、删除。删目录要确认。

另外要能**选中文件, 分享到图床或访客空间**。这不是复制一份文件出去, 也不是私有区冒出一条外链: 底层只新建一条指向记录, 指回磁盘上已经存在的那份内容。唯一真源始终是磁盘。图床页、访客页能看见它, 是因为到了前端接口那边做了分流 — 同一份磁盘内容, 按「出现在哪个空间」决定走哪套列表和哪条公开取法。

分享到图床 = 你主动把这张图放到公开相册里。分享到访客 = 你主动给出一条别人能下的地址。从私有区撤回分享就是删掉那条指向记录, 磁盘文件还在, 除非三个空间都不再指向它。

### 页面

登录后的「文件」页。能看见当前路径、文件列表、自己还剩多少空间。前端没定档, 这里只要求行为, 不写死路由长什么样。不要做成 OpenList 那种挂一堆存储源的样子。

### 和另外两块的边界

私有文件默认不会出现在图床或访客的公开地址里。只有上面说的「分享到…」才会在对应空间多一条指向。想当博客封面, 也是先分享到图床, 再在图床里拿 URL。

路径不能逃出私有根目录。上传下载都不要把整文件读进后端内存。指向记录、去重、磁盘怎么放, 写在第 6 章。

## 3. 图床

这一页就是一个图片墙。主页模仿 `https://photos.google.com/`, 按相册把图铺开, 能切相册、点开大图。谁都能看。上传、建相册、打标签、删除、复制链接, 这些是登录之后才解锁的管理功能。

### 能做什么

未登录: 逛相册, 看图。每张图有一条稳定的公开地址, 封面和外链都用它。

登录后: 往相册里传图、新建相册、打标签 / 按标签筛、复制 URL、从墙上拿掉一张图。私有区「分享到图床」在这里多一条指向: 墙上多一张, 磁盘还是那一份。从图床拿掉 = 删指向, 不删私有文件。

### 页面

就是图片墙, 不是文件列表外面再套一层相册。前端没定档, 只要求进门就是按相册看图。管理动作叠在登录态上, 不要做成一个不鉴权的后台。

### 和另外两块的边界

图床只挂图。访客空间是另一页, 那是阉割版文件资源管理器, 不是第二面墙。博客封面就是墙上某张图的 URL。

图文件不要经后端内存, 交给前面的静态输出。指向和磁盘怎么放写第 6 章, 公开页防风暴写第 5 章。

---

## 4. 访客空间

这一页就是一个阉割版文件资源管理器: 能传、能下, 没有完整的目录树, 也没有公开的整仓列表。谁都能进。上传、拿着链接下载, 未登录就能做。列出全部文件、删除、清空, 以及从私有区接过来的分享, 这些是登录之后才解锁的管理功能。

### 能做什么

未登录: 丢一个文件上去, 当场拿到一条下载地址; 有地址就能下。关掉页面前看不到第二条路找回这个文件 — 没有公开目录可翻。访客文件不是永久存的: 上传 24 小时后自动过期, 上传成功的响应里必须当场连下载地址一起把过期时间摆出来。过期 = 删指向, 磁盘引用计数归 0 才真正删那份内容。

登录后: 看到访客空间里有什么、单条删、一键清空。私有区「分享到访客」在这里多一条指向: 多一个别人能下的地址, 磁盘还是那一份。从访客空间拿掉 = 删指向, 不删私有文件。

### 页面

就是瘦资源管理器, 不是图片墙, 也不是私有区那套完整树。未登录主要是一个上传口和成功后的链接; 登录后才铺开管理列表。前端没定档, 只要求这两态分得清。

### 和另外两块的边界

访客空间什么常见文件都可以收 (具体类型第 6 章说), 但不是第二个私有盘, 也不是第二面图床墙。公开页必须防风暴, 写第 5 章。指向和磁盘怎么放写第 6 章。

## 5. 鉴权与防护

鉴权和防护不是一件事。鉴权管「谁能进私有存储、谁能碰管理接口」。防护管「请求进来之后别把机器打穿」, 面更宽。

### 鉴权

主要护两块: 私有存储的全部读写, 以及三个空间上那一堆管理接口 (建相册、打标签、删图、访客列表/清空、从私有区分享出去、撤回指向, 等等)。

没登录可以逛图床墙、可以往访客空间传/按链接下。这些公开动作不发通行证, 但要走下面的防护。登录态怎么发、怎么收, 放到第 7、8 章和实现一起定, 这里只要求: 管理接口没有登录态就拒绝, 私有存储没有登录态就当不存在。

### 防护

公开页和上传口是冲着外网的, 要比私有区更防着点。至少包括这些:

* **风暴**: 图床墙、访客上传/下载、登录接口, 用 Redis 做短时计数, 超了就挡。不要让公开页把进程或带宽拖死。访客上传单独按 IP 限: 每小时 10 次 / 200MB, 每天 500MB, 超限回 429。`/public/guest/` 的下载在 nginx 层限速: `limit_conn` 每 IP 4 连接 + `limit_rate 2m`。公开文件直出不经过后端, 做不到下载字节级的精确账本, 这是有意的权衡 — 防被当免费 CDN 刷带宽, 但不做精确计量
* **密码爆破**: 登录失败按 IP 记, 同样走 Redis, 和风暴是一类计数、不同桶
* **路径穿越**: 私有存储的路径必须关在自己的根里, `..`、绝对路径、往根外指的链接都不能过
* **后端代码执行**: 用户丢上来的东西当数据, 不当脚本。别拼进 shell。html / svg 可以收, 当普通文本文件处理: 按 `text/plain` 送出, 并关掉内容类型嗅探, 浏览器就只是在看一段字, 不会当成页面或矢量图执行
* **数据库注入**: 问 Postgres 只用参数绑定, 不要把文件名、路径、标签拼进 SQL 字符串

还有同类的: 上传看类型和大小, 不要跟着符号链接逃出数据根。细节随实现补, 但这类口子不能靠「以后再说」漏掉。

## 6. 数据与去重

三个空间看到的不是三份文件, 是同一块磁盘上的内容被指了多次。**唯一真源是磁盘。** Postgres 里存的是指向、相册、标签、用量这些要查询的东西。接口按空间分流: 同一份内容出现在私有存储、图床还是访客, 决定走哪套列表、哪条取法。

数据根在 `/var/lib/yukipan`。

### 磁盘

```text
/var/lib/yukipan/
  blobs/{aa}/{sha256}    # 按内容只放一份, 无扩展名; aa 是 hash 前两位
  private/{user_id}/     # 私有区看见的树, 文件是指向 blob 的 hardlink
  public/images/         # 图床墙上的文件名, 同样是 hardlink
  public/guest/          # 访客空间的文件名, 同样是 hardlink
  tmp/                   # 上传尚未收编
```

区目录里用 hardlink, 不用 symlink (前面防护也不许顺着软链逃出去)。图床、访客的公开取法对着 `public/` 下这些名字; 私有区没有公开地址, 下载走鉴权之后的内部重定向, 具体绑法见第 8 章。

图床墙上只挂图: `jpg jpeg png gif webp avif`。html / svg 不当图片渲染, 进私有存储或访客空间即可, 当普通文本看、下。访客另加常见文档和压缩包 (`pdf zip 7z txt md` 以及图片)。js 若也要收, 同样当文本, 不要按脚本的类型送出去。

### 指向

一条指向 = 「这个空间里的这个名字, 指着磁盘上的这份内容」。分享到图床或访客, 就是新建一条指向, 不复制字节。撤回分享、从图床墙上拿掉、从访客列表删掉, 都是删指向。

引用计数 = 三个空间里还指着这个 hash 的行数。降到 0, 才删 `blobs/` 里那一份。三个空间都不要了, 磁盘才真正丢掉。

私有区的**目录**以文件系统为准 (空目录没有 blob)。**文件**落盘时同时写一条指向。图床和访客没有完整目录树, 列表以库为准。

### 去重与秒传

内容用 SHA-256 (64 位小写 hex) 认。上传边收边算; 已经有这个 hash, 临时文件丢掉, 只 hardlink。客户端大文件必须分块算 hash, 不要整份读进内存。

秒传是「库里已经有、而且你已经拥有至少一条指向」时, 不再传文件体, 只加指向。只知道 hash、没有任何指向, 不能秒传 — 否则猜到私有文件的 hash 就能在公开区挂出来。

所以: 私有存储和图床的秒传要登录, 且只能打在自己已经指过的内容上。把私有文件秒传到图床, 等于你主动公开, 允许。访客空间没有秒传; 对方把字节传上来之后, 服务端可以 hardlink 到已有 blob (省盘, 不省对方带宽)。

图床里已经有同一 hash: 直接回到那张图, 不新建、不加配额。换一个相册再挂一次: 新名字 + 新指向, 配额按引用再加一份。

### 配额

按引用计, 不按「盘上实际几份」。同一内容在私有区放两个路径, 账上加两份, 盘上仍是一份。去重省的是磁盘, 账本按你看见的条数走。

另外还要看盘上是不是真的还有空 (系统、日志、tmp 不进账本)。两道都过才能收新内容。秒传几乎不写新字节, 但仍走引用配额。

给网盘的预算按 20G 来: 私有 14G, 图床 2G, 访客 2G, 再留 2G 给 tmp / 库 / 余量。单文件访客 50M、图床 20M 这一档, 实现时可配。

### 库里有什么

Postgres 大约这些表 (名字可调, 关系不要扁):

* 用户、登录会话
* 用量 (每个用户每个空间已用字节)
* blob (sha256, 大小)
* 私有文件指向 (用户 + 逻辑路径 + hash)
* 相册、图床指向 (相册、公开文件名、原名、hash、标签多对多)
* 访客指向 (公开文件名、原名、hash、来源 IP、expires_at)
* 标签 (按用户, 名字规范化后唯一)

后端每小时跑一次 TTL 清扫任务: 删掉过期的访客指向 (expires_at 到点的), 引用计数归 0 的 blob 按上面的规则一并清掉。

Redis 不存文件, 只记第 5 章那些短时计数。

## 7. 接口

JSON 一律 `{ success, data, message }`, 和 YukiLog 同一套。私有下载/预览不是 JSON, 鉴权通过后走内部重定向。图床墙上的图、访客那条下载地址对着 `public/` 直出, 不经过这些 JSON 口。

登录态用 cookie, 同域带着走, 前端不用自己藏令牌。没 cookie 的管理口直接拒绝; 私有存储没 cookie 当不存在。

分享口只开在图床和访客上: 入参是私有路径 (图床再加相册), 新建一条指向。私有区自己不再开一个「分享」口。撤回就是在对应空间删掉那条指向。

### 登录

* `POST /api/auth/login` `{ username, password }` → Set-Cookie, `{ id, username }`
* `POST /api/auth/logout`
* `GET /api/auth/me` → `{ id, username }`

登录失败不区分用户名还是密码, 走第 5 章的爆破计数。

### 配额

* `GET /api/quota` (要登录) → 三个空间的 `{ used, limit }`, 再加上盘上 `{ free, reserve }`, 单位字节

### 私有存储

都要登录。`path` 相对自己的根, 不合法就拒绝, 不要把真实磁盘路径回出去。

* `GET /api/fs/list?path=` 不递归, 目录在前
* `POST /api/fs/mkdir` `{ path }` 按层层创建
* `POST /api/fs/move` `{ from, to }` `to` 含新名字, 中间目录不代建
* `POST /api/fs/delete` `{ path, recursive }`
* `POST /api/fs/upload?path=` multipart `file`, 可选 `sha256`
* `POST /api/fs/instant` `{ path, name, sha256, size }` 规则见第 6 章
* `GET /api/fs/download?path=` 附件下载
* `GET /api/fs/preview?path=` 页内预览

上传/秒传成功回逻辑路径、大小、hash、是否秒传。

### 图床

未登录可以拉相册和墙。改墙要登录。

* `GET /api/albums` 公开
* `GET /api/images/list` 公开, 可按 `album_id` / `tag` 筛, 分页
* `GET /api/tags` 公开, 给墙上筛选用
* `POST /api/albums` `{ name }`
* `POST /api/albums/delete` `{ id }` 非空或默认册不行
* `POST /api/images/upload` multipart, 可选相册和标签
* `POST /api/images/instant` 规则见第 6 章
* `POST /api/images/delete` `{ id }` 删指向
* `POST /api/images/tags` `{ id, tags }` 全量覆盖
* `POST /api/images/share` `{ path, album_id? }` 把私有路径指到图床, 要登录

列表元素带公开 `url`、原名、hash、标签、相册。看图本身用这条 `url`, 不走 JSON。

### 访客

未登录只传。列表和删除要登录。下载有 `url` 就行。

* `POST /api/guest/upload` 匿名, multipart, 回 `{ url, expires_at, ... }`, 前端必须当场连下载地址一起把过期时间展示出来
* `GET /api/guest/list` 要登录, 分页
* `POST /api/guest/delete` `{ id }`
* `POST /api/guest/clear`
* `POST /api/guest/share` `{ path }` 把私有路径指到访客空间, 要登录

没有访客秒传口。

### 探活

* `GET /api/health` → `{ ok: true }`

## 8. 部署

部署体系用兄弟项目 YukiLog 的 `ops/` 那套。仓库根的 `install.sh` / `uninstall.sh` + `yukipan.env` 常量文件的旧方案作废, 不要再写。所有脚本都在 `ops/` 下, 配置集中到 `/etc/yukipan/`, 数据根是 `/var/lib/yukipan`, 前端落在 `/var/www/yukipan`。

### 首次初始化: ops/bootstrap-host.sh

新机器上跑一次, 交互式收集信息: 有 TTY 就逐条提问, 没有 TTY 就从 `YUKIPAN_*` 环境变量读。收集的内容包括域名 (默认 `pan.yeastar.xin`)、证书邮箱、是否在本机装 Postgres / Redis。

做完这些事:

* 生成数据库密码等运行所需的密钥
* 写 `/etc/yukipan/bootstrap.conf` (域名、邮箱这些机器常量) 和 `/etc/yukipan/config.toml` (基于仓库里的 `yukipan/config.example.toml` 实例化, 后端启动读这份)
* 建系统用户和目录树: `/var/lib/yukipan` (数据根)、`/var/www/yukipan/releases/`、`/var/backups/yukipan`
* 装 systemd unit 和 `/usr/local/sbin/` 下的管理命令
* 用 `sed` 把 nginx 模板实例化成站点配置

### 发布: build-release + yukipan-deploy

开发机上跑 `ops/build-release.sh` 打包出 release (后端二进制 + 前端产物 + sha256 MANIFEST)。服务器上跑 `yukipan-deploy` 部署:

* `flock` 防并发部署
* 校验 sha256 / MANIFEST, 对不上就不动
* 解到 `/var/www/yukipan/releases/<版本>/`, 原子切 `current` 软链
* 切换后 30 秒轮询 `/api/health`, 起不来就自动回滚到上一个 release

首次部署完成后创建第一个管理员用户: `sudo /var/www/yukipan/current/bin/yukipan-server user add <用户名>`, 交互式输两遍密码。私有区和所有管理接口都靠这个账号登录。

### 备份与恢复: yukipan-backup / yukipan-restore

`yukipan-backup`: `pg_dump` custom 格式 + `/etc/yukipan/` 配置副本, 落到 `/var/backups/yukipan/`。默认**不**背 `/var/lib/yukipan` 数据本体, 要带数据加 `--with-data` 开关。

`yukipan-restore`: 恢复是危险动作, 必须带 `--confirm-restore`。先恢复进一个临时库, 校验通过再原子交换到正式库。

### HTTPS: ops/enable-https.sh

用 certbot webroot 方式申请证书, 把站点切到 HTTPS。申请前先确认域名解析已经指到这台机器。

### 卸载: ops/uninstall.sh

停并撤掉 unit、nginx 站点、`/usr/local/sbin/` 下的管理命令。默认**保留** `/var/lib/yukipan` (数据)、`/var/backups/yukipan` (备份)、`/etc/yukipan` (配置)。要全删加 `--purge`, 并且必须输入域名确认, 免得手滑。

### 演练: ops/rehearsal/

部署脚本的验证手段, 照搬 YukiLog 的封闭演练体系: 用 `systemd-nspawn` 起一次性 Ubuntu 24.04 容器, 断掉外部网络, 在容器里把 bootstrap → deploy → 升级 → 备份恢复完整跑一遍, 跑之前和跑之后对比宿主机不变量 (容器外的东西一点不许变)。脚本进了 ops/ 就要能过这一关, 不许只在真机上试错。

### nginx 与 systemd

nginx 仍然是: 静态页、`/public/images/` 和 `/public/guest/` 直出、`/protected/` 仅内部、`/api/` 反代到 8516; 访客上传单独限制 body, 其它上传放宽; 反代关掉请求缓冲; `/public/guest/` 那档限流速见第 5 章。直出的数据根是 `/var/lib/yukipan`。TLS 交给 nginx。

systemd unit 带沙箱: `ProtectSystem=strict` + `ReadWritePaths=/var/lib/yukipan`, 后端进程只能写数据根, 别在 unit 和 nginx 配置里再手写一套不一致的路径。
